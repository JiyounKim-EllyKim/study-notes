# LLM 개념 정리

## 1. LLM

LLM은 Large Language Model의 약자로, 대규모 텍스트 데이터로 학습된 언어 모델이다.

한국어로는 대규모 언어 모델이라고 한다.

LLM은 문장, 문서, 코드 등 다양한 텍스트 데이터를 학습하여 주어진 입력에 맞는 자연어를 생성하거나 분석할 수 있다.

---

## 2. Language Model

Language Model은 문맥을 바탕으로 다음에 올 단어나 토큰의 확률을 예측하는 모델이다.

```text id="edw7vu"
나는 오늘 학교에
→ 갔다
→ 간다
→ 가고
```

모델은 앞에 나온 문맥을 보고 다음에 어떤 단어가 자연스러운지 예측한다.

LLM은 이런 Language Model을 매우 큰 규모의 데이터와 파라미터로 확장한 모델이다.

---

## 3. LLM의 기본 아이디어

LLM은 텍스트의 패턴을 학습하여 새로운 텍스트를 생성한다.

주어진 입력을 이해하고, 그 다음에 올 가능성이 높은 토큰을 하나씩 예측하면서 답변을 만든다.

```text id="fywluj"
입력 Prompt
→ Tokenization
→ 모델 추론
→ 다음 Token 예측
→ 반복 생성
→ 최종 응답
```

즉, LLM의 답변은 한 번에 완성되는 것이 아니라 토큰 단위로 순차적으로 생성된다.

---

## 4. Token

Token은 LLM이 텍스트를 처리하는 기본 단위이다.

토큰은 단어, 문자, 서브워드 등으로 구성될 수 있다.

```text id="7e9d0s"
문장: 나는 오늘 공부한다
Token: 나는 / 오늘 / 공부 / 한다
```

LLM은 문장을 그대로 이해하는 것이 아니라, 토큰 단위로 나누어 처리한다.

---

## 5. Next Token Prediction

Next Token Prediction은 현재까지의 문맥을 바탕으로 다음 토큰을 예측하는 방식이다.

LLM은 학습 과정에서 수많은 문장을 보고 다음 토큰을 맞추는 방식으로 언어 패턴을 학습한다.

```text id="t1upya"
입력: 인공지능은 데이터를 기반으로
예측: 학습한다
```

이 과정을 반복하면 문장이나 문단 단위의 긴 응답을 생성할 수 있다.

---

## 6. Pre-training

Pre-training은 대규모 텍스트 데이터로 모델을 미리 학습시키는 과정이다.

LLM은 Pre-training을 통해 문법, 단어 의미, 문맥, 상식, 코드 패턴 등 다양한 언어적 지식을 학습한다.

### 특징

* 매우 많은 데이터가 필요하다.
* 많은 연산 자원이 필요하다.
* 일반적인 언어 패턴을 학습한다.
* 이후 다양한 작업에 활용할 수 있는 기반 모델을 만든다.

---

## 7. Fine-tuning

Fine-tuning은 Pre-trained Model을 특정 작업이나 도메인에 맞게 추가 학습하는 과정이다.

예를 들어 일반적인 언어 모델을 고객 상담 데이터로 Fine-tuning하면 고객 문의 응답에 더 적합한 모델을 만들 수 있다.

```text id="m7ytwd"
Pre-trained LLM
→ 특정 도메인 데이터 추가 학습
→ Task-specific Model
```

Fine-tuning은 모델의 응답 스타일이나 특정 작업 성능을 개선하는 데 사용할 수 있다.

---

## 8. Instruction Tuning

Instruction Tuning은 모델이 사람의 지시를 더 잘 따르도록 학습시키는 과정이다.

일반적인 언어 모델은 다음 토큰을 예측하는 능력은 뛰어나지만, 사용자의 요청을 정확히 수행하는 능력은 부족할 수 있다.

Instruction Tuning을 통해 모델은 질문 답변, 요약, 번역, 분류, 코드 작성 같은 지시를 더 잘 수행하도록 학습된다.

---

## 9. Alignment

Alignment는 LLM이 사용자의 의도와 사회적 기준에 맞는 답변을 하도록 조정하는 과정이다.

모델이 단순히 그럴듯한 텍스트를 생성하는 것을 넘어, 유용하고 안전하며 신뢰할 수 있는 방향으로 응답하도록 만드는 것이 목적이다.

### 고려 요소

* 유용성
* 정확성
* 안전성
* 편향 완화
* 사용자 의도 반영
* 부적절한 출력 방지

---

## 10. Transformer와 LLM

대부분의 현대 LLM은 Transformer 구조를 기반으로 한다.

Transformer는 Self-Attention을 사용해 입력 토큰들 사이의 관계를 계산한다.

이를 통해 모델은 문장 안에서 어떤 단어가 서로 관련 있는지 파악하고, 문맥을 반영한 출력을 만들 수 있다.

```text id="ouje1g"
Token Embedding
→ Positional Encoding
→ Transformer Layers
→ Output Probability
→ Next Token
```

---

## 11. Attention

Attention은 입력 토큰 중 어떤 정보에 더 집중할지 계산하는 방법이다.

LLM은 Attention을 통해 문장 안의 여러 단어 사이의 관계를 파악한다.

예를 들어 대명사가 무엇을 가리키는지, 문장의 핵심 주제가 무엇인지 판단할 때 Attention이 사용될 수 있다.

---

## 12. Context Window

Context Window는 모델이 한 번에 참고할 수 있는 입력과 출력의 최대 길이를 의미한다.

LLM은 무한히 긴 대화를 모두 기억하는 것이 아니라, 정해진 Context Window 안의 토큰을 바탕으로 응답을 생성한다.

### 주의할 점

* 입력이 너무 길면 일부 내용이 잘릴 수 있다.
* 긴 문서를 처리할 때는 요약이나 검색 구조가 필요할 수 있다.
* 중요한 정보는 Prompt 안에 명확히 포함하는 것이 좋다.

---

## 13. Prompt

Prompt는 LLM에게 전달하는 입력이다.

Prompt에는 사용자의 질문, 작업 지시, 배경 정보, 제약 조건, 예시 등이 포함될 수 있다.

```text id="a9sebp"
다음 문장을 긍정/부정으로 분류해줘.
문장: 배송이 너무 늦어서 실망했어.
```

LLM의 출력은 Prompt 구성에 큰 영향을 받는다.

---

## 14. Prompt Engineering

Prompt Engineering은 LLM이 원하는 작업을 더 잘 수행하도록 입력을 설계하는 과정이다.

좋은 Prompt는 작업 목표, 출력 형식, 필요한 맥락, 제약 조건을 명확하게 전달한다.

### 포함할 수 있는 요소

* 역할 Role
* 작업 지시 Instruction
* 배경 정보 Context
* 예시 Example
* 출력 형식 Output Format
* 제약 조건 Constraint

Prompt Engineering은 LLM 활용에서 매우 중요한 기술이다.

---

## 15. Zero-shot Prompting

Zero-shot Prompting은 별도의 예시 없이 작업 지시만으로 모델에게 작업을 수행하게 하는 방법이다.

```text id="sr7xv9"
다음 문장을 긍정/부정으로 분류해줘.

문장: 제품이 정말 마음에 들어요.
```

모델이 이미 학습한 지식을 바탕으로 작업을 수행한다.

---

## 16. Few-shot Prompting

Few-shot Prompting은 몇 개의 예시를 Prompt에 포함하여 모델이 원하는 방식으로 답변하도록 유도하는 방법이다.

```text id="kh1tkp"
문장: 배송이 빨라요.
라벨: 긍정

문장: 품질이 별로예요.
라벨: 부정

문장: 가격이 합리적이에요.
라벨:
```

예시를 제공하면 모델이 출력 형식과 판단 기준을 더 잘 따를 수 있다.

---

## 17. Embedding

Embedding은 텍스트의 의미를 숫자 벡터로 표현하는 방법이다.

LLM 기반 서비스에서는 문장이나 문서를 Embedding으로 변환하여 유사도 검색에 활용할 수 있다.

```text id="gn28tv"
문서
→ Embedding Model
→ Vector
→ Similarity Search
```

Embedding은 RAG, 추천, 검색, 문서 클러스터링 등에 자주 사용된다.

---

## 18. Vector Database

Vector Database는 Embedding 벡터를 저장하고 검색하기 위한 데이터베이스이다.

일반적인 키워드 검색이 단어 일치 여부를 중심으로 검색한다면, Vector DB는 의미적으로 비슷한 문서를 찾는 데 사용할 수 있다.

### 활용 예시

* 문서 검색
* 유사 질문 검색
* RAG 검색 단계
* 추천 시스템
* 의미 기반 검색

---

## 19. RAG

RAG는 Retrieval-Augmented Generation의 약자로, 검색 증강 생성이라고 한다.

LLM이 답변을 생성하기 전에 외부 문서나 데이터베이스에서 관련 정보를 검색하고, 그 정보를 Prompt에 넣어 답변하도록 만드는 방식이다.

```text id="gpruvh"
사용자 질문
→ 관련 문서 검색
→ 검색 결과를 Prompt에 추가
→ LLM 답변 생성
```

RAG는 LLM이 학습하지 않았거나 최신성이 필요한 정보를 다룰 때 유용하다.

---

## 20. Hallucination

Hallucination은 LLM이 실제로는 근거가 없거나 틀린 내용을 그럴듯하게 생성하는 현상이다.

한국어로는 환각이라고도 한다.

LLM은 확률적으로 자연스러운 문장을 생성하기 때문에, 모르는 내용에 대해서도 확신 있는 말투로 잘못된 답변을 만들 수 있다.

### 줄이는 방법

* 근거 문서 제공
* RAG 사용
* 답변에 출처 포함
* 모르는 내용은 모른다고 답하도록 지시
* 모델 출력 검증
* 평가 데이터셋 구축

---

## 21. Agent

Agent는 LLM이 단순히 답변만 생성하는 것이 아니라, 도구를 사용하거나 여러 단계를 거쳐 작업을 수행하도록 만든 시스템이다.

예를 들어 검색, 계산, 데이터베이스 조회, 코드 실행 같은 도구를 LLM이 선택하여 사용할 수 있다.

```text id="7ks0mg"
User Request
→ LLM 판단
→ Tool 사용
→ 결과 확인
→ 다음 행동 결정
→ Final Answer
```

Agent는 복잡한 작업을 자동화하는 데 활용된다.

---

## 22. Tool Calling

Tool Calling은 LLM이 필요한 도구를 호출하여 외부 기능을 사용하는 방식이다.

LLM 자체는 계산, 검색, 데이터베이스 조회를 완벽하게 수행하지 못할 수 있다.
이때 외부 도구를 연결하면 더 정확하고 유용한 결과를 만들 수 있다.

### 예시

* 웹 검색
* 계산기
* 데이터베이스 조회
* 파일 읽기
* 코드 실행
* API 호출

---

## 23. LLM Application

LLM Application은 LLM을 활용해 실제 문제를 해결하는 서비스나 시스템이다.

대표적인 LLM Application 구조는 다음과 같다.

| 유형                   | 설명                  |
| -------------------- | ------------------- |
| Chatbot              | 사용자와 대화하는 시스템       |
| RAG QA System        | 문서를 검색해 근거 기반 답변 생성 |
| Summarization System | 긴 문서를 요약            |
| Text Classification  | 문장이나 문서를 분류         |
| Agent System         | 도구를 사용해 복잡한 작업 수행   |
| Code Assistant       | 코드 작성과 디버깅 지원       |

---

## 24. LLM Evaluation

LLM Evaluation은 LLM의 출력이 좋은지 평가하는 과정이다.

LLM은 정답이 하나로 정해지지 않는 작업이 많기 때문에 평가가 어렵다.

### 평가 기준 예시

* 정확성
* 관련성
* 완전성
* 일관성
* 근거 충실성
* 유해성 여부
* 사용자의 요구사항 준수
* 응답 형식 준수

LLM 서비스에서는 자동 평가와 사람 평가를 함께 사용하는 경우가 많다.

---

## 25. LLM의 장점

LLM은 다양한 언어 작업을 하나의 모델로 수행할 수 있다.

### 장점

* 자연어 이해와 생성이 가능하다.
* 다양한 작업에 범용적으로 활용할 수 있다.
* Prompt만으로 새로운 작업을 수행할 수 있다.
* 요약, 번역, 분류, 질의응답, 코드 작성 등에 활용된다.
* RAG나 Agent 구조와 결합해 실제 서비스로 확장할 수 있다.

---

## 26. LLM의 한계

LLM은 강력하지만 한계도 있다.

### 한계

* 틀린 내용을 그럴듯하게 생성할 수 있다.
* 학습 데이터에 없는 최신 정보를 알지 못할 수 있다.
* 입력 길이에 제한이 있다.
* 민감한 정보나 편향 문제가 발생할 수 있다.
* 결과를 항상 그대로 신뢰하기 어렵다.
* 모델 사용 비용과 추론 속도를 고려해야 한다.

---

## 27. LLM 사용 시 주의할 점

* 중요한 정보는 근거 문서와 함께 제공해야 한다.
* 최신 정보가 필요한 경우 외부 검색이나 RAG가 필요할 수 있다.
* 모델이 모르는 내용을 만들어낼 수 있으므로 검증이 필요하다.
* 개인정보나 민감한 데이터를 입력할 때 주의해야 한다.
* Prompt와 출력 형식을 명확히 설계해야 한다.
* 실제 서비스에서는 평가와 모니터링이 필요하다.

---

## 28. LLM 활용 분야

LLM은 다양한 분야에서 활용될 수 있다.

| 분야     | 활용 예시               |
| ------ | ------------------- |
| 검색     | 의미 기반 검색, 문서 QA     |
| 고객 응대  | 챗봇, 문의 자동 응답        |
| 교육     | 학습 도우미, 피드백 생성      |
| 금융     | 뉴스 요약, 리포트 생성       |
| 법률     | 계약서 요약, 조항 검색       |
| 개발     | 코드 생성, 코드 리뷰        |
| 데이터 분석 | 자연어 기반 데이터 질의       |
| 채용     | 자기소개서 피드백, 면접 질문 생성 |

## 29. NLP와 LLM의 관계

LLM은 NLP 기술의 발전 흐름 속에서 등장한 대규모 언어 모델이다.

기존 NLP는 작업별로 모델을 따로 학습하는 경우가 많았지만, LLM은 하나의 모델로 다양한 작업을 수행할 수 있다.

```text id="18r3p6"
NLP
→ Language Model
→ Transformer
→ Large Language Model
```

LLM을 제대로 이해하려면 NLP, 딥러닝, Transformer, Embedding 개념을 함께 이해하는 것이 좋다.

---

## 30. 정리

* LLM은 대규모 텍스트 데이터로 학습된 언어 모델이다.
* Language Model은 문맥을 바탕으로 다음 토큰을 예측한다.
* LLM은 토큰 단위로 출력을 생성한다.
* Pre-training은 대규모 데이터로 모델을 미리 학습하는 과정이다.
* Fine-tuning은 특정 작업이나 도메인에 맞게 추가 학습하는 과정이다.
* Instruction Tuning은 모델이 지시를 잘 따르도록 학습시키는 과정이다.
* 대부분의 현대 LLM은 Transformer 구조를 기반으로 한다.
* Prompt는 LLM에게 전달하는 입력이다.
* Prompt Engineering은 원하는 출력을 얻기 위해 Prompt를 설계하는 과정이다.
* Embedding은 텍스트 의미를 벡터로 표현하는 방법이다.
* RAG는 외부 문서를 검색해 LLM 답변에 활용하는 방식이다.
* Hallucination은 모델이 근거 없는 내용을 그럴듯하게 생성하는 현상이다.
* Agent는 LLM이 도구를 사용해 복잡한 작업을 수행하도록 만든 시스템이다.
* LLM은 강력하지만 검증, 평가, 안전성 관리가 필요하다.
