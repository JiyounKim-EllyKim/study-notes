# Hallucination 개념 정리

## 1. Hallucination

Hallucination은 LLM이 실제로는 근거가 없거나 틀린 내용을 그럴듯하게 생성하는 현상이다.

한국어로는 환각이라고도 한다.

LLM은 자연스러운 문장을 생성하는 데 강하지만, 항상 사실만 말하는 것은 아니다.  
모델이 모르는 내용이나 불확실한 내용에 대해서도 확신 있는 말투로 답변을 만들 수 있다.

---

## 2. Hallucination이 중요한 이유

LLM 서비스에서는 답변이 자연스러운 것만으로 충분하지 않다.

특히 금융, 의료, 법률, 채용, 교육, 사내 문서 검색처럼 정확성이 중요한 분야에서는 잘못된 답변이 큰 문제로 이어질 수 있다.

### 문제가 되는 이유

- 사용자가 틀린 정보를 사실로 믿을 수 있다.
- 잘못된 의사결정으로 이어질 수 있다.
- 서비스 신뢰도가 떨어질 수 있다.
- 문서 기반 QA에서 근거 없는 답변이 생성될 수 있다.
- 출처나 인용까지 잘못 만들어낼 수 있다.

---

## 3. Hallucination 예시

```text id="8a7n49"
질문:
A 프로젝트의 최종 발표일이 언제야?

실제 문서:
최종 발표일 정보 없음

잘못된 답변:
A 프로젝트의 최종 발표일은 2026년 7월 16일입니다.
```

문서에 없는 내용을 모델이 임의로 생성하면 Hallucination에 해당한다.

---

## 4. Hallucination의 유형

Hallucination은 여러 형태로 나타날 수 있다.

| 유형 | 설명 |
|---|---|
| Factual Hallucination | 사실과 다른 내용을 생성 |
| Source Hallucination | 존재하지 않는 출처나 문서를 생성 |
| Citation Hallucination | 출처와 맞지 않는 내용을 인용 |
| Numerical Hallucination | 숫자, 날짜, 비율 등을 잘못 생성 |
| Context Hallucination | 제공된 문맥에 없는 내용을 추가 |
| Reasoning Hallucination | 논리적으로 맞지 않는 추론을 생성 |

---

## 5. Factual Hallucination

Factual Hallucination은 사실과 다른 내용을 생성하는 경우이다.

```text id="lz7mqv"
질문:
이 회사의 2026년 매출은 얼마야?

잘못된 답변:
2026년 매출은 3조 원입니다.
```

실제 근거가 없거나 수치가 확인되지 않았는데 특정 수치를 말하면 문제가 된다.

---

## 6. Source Hallucination

Source Hallucination은 존재하지 않는 출처나 문서를 만들어내는 경우이다.

```text id="447wrm"
잘못된 답변:
이 내용은 2026년 OpenAI 공식 보고서에 따르면 확인됩니다.
```

실제로 해당 보고서가 없거나, 보고서에 그런 내용이 없다면 Hallucination이다.

---

## 7. Citation Hallucination

Citation Hallucination은 출처는 존재하지만, 그 출처가 답변 내용을 실제로 뒷받침하지 않는 경우이다.

```text id="foh2e8"
문서 A:
프로젝트 기간만 설명함

잘못된 답변:
문서 A에 따르면 모델 성능은 AUC 0.94입니다.
```

출처가 있어 보이더라도, 해당 출처가 실제 주장을 지원하는지 확인해야 한다.

---

## 8. Numerical Hallucination

Numerical Hallucination은 숫자, 날짜, 비율, 순위 등을 잘못 생성하는 경우이다.

LLM은 숫자 계산이나 정확한 날짜 기억에 약할 수 있다.

### 예시

- 지원 마감일을 잘못 말함
- 시험 날짜를 잘못 말함
- 성능 수치를 임의로 생성함
- 퍼센트 계산을 틀림
- 표의 수치를 잘못 요약함

숫자 정보는 특히 원문이나 계산 도구로 검증하는 것이 중요하다.

---

## 9. Context Hallucination

Context Hallucination은 제공된 문맥에 없는 내용을 추가하는 경우이다.

```text id="ey35b8"
제공 문서:
프로젝트는 Django와 React를 사용했다.

잘못된 답변:
이 프로젝트는 Django, React, Kubernetes를 사용했다.
```

Kubernetes가 문서에 없는데 추가했다면 Hallucination이다.

문서 기반 답변에서는 제공된 자료 안에서 확인되는 내용만 사용해야 한다.

---

## 10. Hallucination이 발생하는 이유

Hallucination은 여러 이유로 발생할 수 있다.

- LLM이 다음 토큰을 확률적으로 생성하기 때문
- 모델이 최신 정보를 알지 못할 수 있기 때문
- 학습 데이터에 잘못된 정보가 포함되었을 수 있기 때문
- Prompt가 모호하기 때문
- 제공된 문맥이 부족하기 때문
- 검색된 문서가 질문과 관련 없기 때문
- 모델이 모르는 내용을 인정하지 않고 답하려 하기 때문
- 숫자나 출처를 정확히 검증하지 못하기 때문

---

## 11. Next Token Prediction과 Hallucination

LLM은 기본적으로 다음에 올 가능성이 높은 토큰을 예측하는 방식으로 문장을 생성한다.

즉, 모델은 데이터베이스처럼 사실을 조회해서 답하는 것이 아니라, 문맥상 자연스러운 답변을 생성한다.

```text id="c6e89q"
현재 문맥
→ 다음 토큰 예측
→ 다음 토큰 예측
→ 문장 생성
```

이 특성 때문에 자연스럽지만 틀린 문장이 생성될 수 있다.

---

## 12. Knowledge Cutoff와 Hallucination

LLM은 학습 시점 이후의 정보를 알지 못할 수 있다.

최신 채용 공고, 법률, 가격, 일정, 뉴스, 기업 정보처럼 자주 바뀌는 정보는 모델 내부 지식만으로 답하면 틀릴 가능성이 있다.

이런 경우에는 검색, API, 데이터베이스, RAG 같은 외부 정보 연결이 필요하다.

---

## 13. Prompt 모호성과 Hallucination

Prompt가 모호하면 모델이 부족한 정보를 임의로 채울 수 있다.

### 모호한 Prompt

```text id="iyhf6c"
이 프로젝트 정리해줘.
```

### 더 안전한 Prompt

```text id="z4jiz6"
아래 프로젝트 설명에 있는 내용만 사용해서 정리해줘.
설명에 없는 내용은 추가하지 말고, 확인되지 않는 내용은 "확인되지 않음"이라고 표시해줘.
```

답변 범위와 근거 사용 방식을 명확히 하면 Hallucination을 줄일 수 있다.

---

## 14. Grounding

Grounding은 모델이 특정 근거 자료에 기반해 답변하도록 만드는 것이다.

LLM에게 문서, 데이터, 표, 검색 결과 등을 제공하고 그 안에서만 답하게 하면 Hallucination을 줄일 수 있다.

```text id="nsi60c"
제공된 문서만 근거로 답변해줘.
문서에 없는 내용은 추측하지 말고 확인되지 않는다고 말해줘.
```

Grounding은 RAG와 문서 기반 QA에서 매우 중요하다.

---

## 15. RAG와 Hallucination

RAG는 Hallucination을 줄이는 대표적인 방법이다.

RAG는 LLM이 답변하기 전에 관련 문서를 검색하고, 그 문서를 근거로 답변을 생성하도록 한다.

```text id="7jzmwg"
User Question
→ Document Retrieval
→ Retrieved Context
→ Grounded Answer
```

하지만 RAG를 사용한다고 Hallucination이 완전히 사라지는 것은 아니다.

---

## 16. RAG에서도 Hallucination이 생기는 경우

RAG에서도 다음과 같은 상황에서는 Hallucination이 발생할 수 있다.

- 검색된 문서가 질문과 관련이 없음
- 필요한 문서가 검색되지 않음
- 문서 내용이 오래되었거나 틀림
- Chunk가 잘못 잘려 문맥이 부족함
- LLM이 검색된 문서를 잘못 해석함
- 문서에 없는 내용을 답변에 추가함
- Citation이 실제 근거와 맞지 않음

따라서 RAG에서는 검색 품질과 답변 충실성을 함께 평가해야 한다.

---

## 17. Hallucination을 줄이는 Prompt 전략

Prompt만으로 Hallucination을 완전히 막을 수는 없지만, 줄이는 데 도움이 된다.

### 전략

- 제공된 자료만 사용하도록 지시
- 모르는 내용은 모른다고 답하게 하기
- 추측과 사실을 구분하게 하기
- 답변에 근거를 포함하게 하기
- 출력 형식을 제한하기
- 불확실한 내용은 표시하게 하기
- 숫자와 날짜는 원문 기준으로 확인하게 하기

---

## 18. 안전한 Prompt 예시

```text id="xrpzsc"
아래 문서 내용만 근거로 답변해줘.

규칙:
- 문서에 없는 내용은 추가하지 않는다.
- 확인되지 않는 내용은 "문서에서 확인되지 않음"이라고 쓴다.
- 숫자, 날짜, 고유명사는 문서 표현을 그대로 사용한다.
- 답변 마지막에 사용한 근거 문장을 함께 정리한다.

문서:
{document}

질문:
{question}
```

이런 Prompt는 모델이 근거 없는 내용을 추가하는 것을 줄이는 데 도움이 된다.

---

## 19. 검색 품질 개선

RAG에서 Hallucination을 줄이려면 검색 품질을 높여야 한다.

관련 문서를 제대로 검색하지 못하면 LLM은 부족한 정보를 임의로 채울 수 있다.

### 개선 방법

- Chunk Size 조정
- Chunk Overlap 설정
- Embedding Model 변경
- Hybrid Search 사용
- Metadata Filtering 사용
- Reranking 사용
- Query Rewriting 사용
- Top-k 값 조정
- 문서 품질 개선

---

## 20. Hybrid Search와 Hallucination

Hybrid Search는 키워드 검색과 벡터 검색을 함께 사용하는 방식이다.

정확한 고유명사, 날짜, 숫자, 코드명은 Vector Search만으로 놓칠 수 있다.

```text id="vdsp8v"
Vector Search:
의미적으로 비슷한 문서 검색

Keyword Search:
정확한 단어가 포함된 문서 검색
```

Hybrid Search를 사용하면 검색 누락을 줄이고, 근거 없는 답변 가능성을 낮출 수 있다.

---

## 21. Reranking과 Hallucination

Reranking은 1차 검색 결과를 다시 정렬하여 질문과 더 관련 있는 문서를 상위에 배치하는 과정이다.

검색 결과에 관련 없는 문서가 많이 포함되면 LLM이 잘못된 근거를 사용할 수 있다.

Reranking은 Prompt에 들어가는 문서 품질을 높여 Hallucination을 줄이는 데 도움이 된다.

---

## 22. Citation 관리

Citation은 답변의 근거 출처를 표시하는 것이다.

문서 기반 QA에서는 답변이 어떤 문서의 어떤 내용에 근거했는지 추적할 수 있어야 한다.

### 주의할 점

- 답변 내용과 Citation이 실제로 일치해야 한다.
- 출처만 붙어 있다고 정답은 아니다.
- 문서에 없는 내용을 Citation으로 포장하면 안 된다.
- 페이지, 문단, Chunk ID 같은 세부 위치를 관리하면 좋다.

Citation은 신뢰도를 높이는 도구이지만, 잘못 사용하면 오히려 위험하다.

---

## 23. 답변 후 검증

중요한 작업에서는 LLM의 답변을 생성한 뒤 검증 단계를 추가할 수 있다.

### 검증 예시

- 답변의 각 문장이 문서에 근거하는지 확인
- 숫자와 날짜가 원문과 일치하는지 확인
- 출처가 실제 내용을 뒷받침하는지 확인
- 문서에 없는 주장이 포함되었는지 확인
- 질문에 직접 답했는지 확인

RAG 시스템에서는 생성 단계와 검증 단계를 분리하는 방식도 사용할 수 있다.

---

## 24. 불확실성 표현

LLM은 불확실한 내용에 대해 확신 있는 말투로 답할 수 있다.

서비스에서는 모델이 모르는 내용을 인정하도록 설계하는 것이 중요하다.

### 좋은 표현

```text id="myrs07"
제공된 문서에서는 해당 내용을 확인할 수 없습니다.
현재 자료만으로는 판단하기 어렵습니다.
추가 문서가 필요합니다.
```

불확실성을 명확히 표현하면 잘못된 정보 전달을 줄일 수 있다.

---

## 25. Human-in-the-loop

Human-in-the-loop은 사람이 모델 출력의 일부 또는 전체를 검토하는 방식이다.

정확성이 중요한 업무에서는 LLM이 생성한 답변을 사람이 최종 확인하는 구조가 필요할 수 있다.

### 필요한 경우

- 법률 문서 검토
- 금융 리포트 생성
- 의료 정보 요약
- 채용 평가
- 공문 작성
- 고객에게 직접 전달되는 중요 답변

LLM은 보조 도구로 사용하고, 최종 판단은 사람이 검토하는 구조가 안전하다.

---

## 26. Hallucination 평가

Hallucination을 줄이려면 평가 기준을 정해야 한다.

단순히 답변이 자연스러운지만 보면 안 되고, 근거와 사실성을 확인해야 한다.

### 평가 기준

| 기준 | 설명 |
|---|---|
| Factuality | 사실과 일치하는가 |
| Faithfulness | 제공된 근거에 충실한가 |
| Groundedness | 답변이 문서에 기반하는가 |
| Citation Accuracy | 인용이 실제 근거와 연결되는가 |
| Completeness | 질문에 충분히 답했는가 |
| Uncertainty Handling | 모르는 내용을 모른다고 말하는가 |

---

## 27. Faithfulness

Faithfulness는 답변이 제공된 근거 문서에 충실한지를 의미한다.

답변이 사실처럼 보이더라도, 제공된 문서에 없는 내용이면 Faithfulness가 낮다.

```text id="qw9ole"
문서:
A 기능은 질문 생성 기능이다.

답변:
A 기능은 질문 생성과 답변 평가를 모두 담당한다.
```

문서에 답변 평가 내용이 없다면 근거에 충실하지 않은 답변이다.

---

## 28. Factuality

Factuality는 답변이 실제 사실과 일치하는지를 의미한다.

Faithfulness는 제공된 문서와의 일치 여부를 보고, Factuality는 실제 세계의 사실 여부를 본다.

| 구분 | 기준 |
|---|---|
| Faithfulness | 제공된 근거에 충실한가 |
| Factuality | 실제 사실과 맞는가 |

문서 자체가 틀린 경우, 답변은 문서에는 충실하지만 실제 사실과는 다를 수 있다.

---

## 29. Hallucination 모니터링

LLM 서비스를 운영할 때는 Hallucination 발생 여부를 지속적으로 모니터링해야 한다.

### 모니터링 항목

- 사용자가 신고한 잘못된 답변
- 근거 없는 답변 비율
- Citation 오류
- 검색 실패 케이스
- 특정 질문 유형에서 반복되는 오류
- 모델 업데이트 후 성능 변화
- 문서 업데이트 이후 검색 품질 변화

운영 단계에서는 한 번 평가하고 끝내는 것이 아니라 지속적인 개선이 필요하다.

---

## 30. Hallucination과 사용자 경험

Hallucination을 줄이는 것은 정확성뿐만 아니라 사용자 경험과도 연결된다.

모델이 모르는 것을 모른다고 말하는 답변은 짧게 보면 덜 유용해 보일 수 있지만, 장기적으로는 신뢰도를 높인다.

```text id="m2zv5d"
나쁜 답변:
확인되지 않은 내용을 단정적으로 말함

좋은 답변:
확인 가능한 내용과 확인되지 않은 내용을 구분함
```

LLM 서비스에서는 항상 답하는 것보다, 정확히 답하는 것이 더 중요하다.

---

## 31. Hallucination 방지 체크리스트

LLM 애플리케이션에서 Hallucination을 줄이기 위한 체크리스트는 다음과 같다.

- 답변에 사용할 근거 문서를 제공했는가?
- 문서에 없는 내용을 추가하지 않도록 지시했는가?
- 검색 결과가 질문과 실제로 관련 있는가?
- Citation이 답변 내용을 실제로 뒷받침하는가?
- 숫자, 날짜, 고유명사를 원문과 대조했는가?
- 불확실한 내용은 불확실하다고 표시했는가?
- 중요한 작업은 사람이 검토하는가?
- 검색 품질과 답변 품질을 따로 평가했는가?
- 잘못된 답변 사례를 모아 개선하고 있는가?

## 32. 정리

- Hallucination은 LLM이 근거 없거나 틀린 내용을 그럴듯하게 생성하는 현상이다.
- LLM은 다음 토큰을 확률적으로 생성하기 때문에 자연스럽지만 틀린 답변을 만들 수 있다.
- Hallucination은 사실 오류, 출처 오류, 인용 오류, 숫자 오류, 문맥 오류 등으로 나타날 수 있다.
- 최신 정보나 특정 문서 기반 정보가 필요한 경우 LLM 내부 지식만으로 답하면 위험할 수 있다.
- Grounding은 모델이 특정 근거 자료에 기반해 답변하도록 만드는 것이다.
- RAG는 Hallucination을 줄이는 데 도움이 되지만 완전히 제거하지는 못한다.
- RAG에서는 검색 품질이 낮으면 답변 품질도 낮아진다.
- Prompt에는 문서에 없는 내용을 추측하지 말라는 지시를 명확히 넣는 것이 좋다.
- Citation은 답변의 근거를 보여주지만, 실제로 답변 내용을 뒷받침하는지 확인해야 한다.
- Faithfulness는 답변이 제공된 근거에 충실한지를 의미한다.
- Factuality는 답변이 실제 사실과 일치하는지를 의미한다.
- 중요한 LLM 서비스에서는 평가, 모니터링, Human-in-the-loop 구조가 필요하다.
