Feature Engineering 개념 정리

1. Feature Engineering

Feature Engineering은 모델이 더 잘 학습할 수 있도록 입력 변수 Feature를 만들고, 변환하고, 선택하는 과정이다.

머신러닝에서는 모델 알고리즘만큼이나 데이터와 Feature의 품질이 중요하다.

좋은 Feature는 모델이 데이터의 패턴을 더 쉽게 학습하도록 도와준다.

---

2. Feature Engineering이 필요한 이유

원본 데이터가 항상 모델 학습에 적합한 형태로 주어지는 것은 아니다.

데이터에는 결측치, 이상치, 범주형 변수, 스케일 차이, 불필요한 변수 등이 포함될 수 있다.

Feature Engineering은 이런 데이터를 모델이 이해하기 좋은 형태로 바꾸는 과정이다.

목적

- 모델 성능 향상
- 데이터 품질 개선
- 불필요한 정보 제거
- 중요한 패턴 강조
- 과대적합 완화
- 모델 해석력 향상

---

3. Feature Engineering의 주요 작업

Feature Engineering에는 다음과 같은 작업이 포함된다.

작업| 설명
결측치 처리| 비어 있는 값을 적절히 채우거나 제거
이상치 처리| 비정상적으로 큰 값이나 작은 값 처리
인코딩| 범주형 변수를 숫자로 변환
스케일링| 변수의 범위를 조정
파생 변수 생성| 기존 변수를 조합해 새로운 변수 생성
변수 선택| 중요한 변수만 선택
변수 변환| 로그 변환, 구간화 등 적용

---

4. 결측치 Missing Value 처리

결측치는 데이터에 값이 비어 있는 경우를 의미한다.

결측치가 있으면 일부 모델은 학습을 수행하지 못할 수 있으므로 적절히 처리해야 한다.

처리 방법

방법| 설명
제거| 결측치가 있는 행이나 열 삭제
평균 대체| 수치형 변수의 결측치를 평균값으로 채움
중앙값 대체| 이상치가 있을 때 중앙값으로 채움
최빈값 대체| 범주형 변수의 결측치를 가장 많이 등장한 값으로 채움
별도 범주 처리| 결측 자체를 하나의 범주로 처리
모델 기반 대체| 다른 변수를 이용해 결측값 예측

---

5. 결측치 처리 시 주의할 점

결측치를 무조건 제거하면 데이터 손실이 커질 수 있다.

반대로 단순히 평균값으로 채우면 데이터의 분포가 왜곡될 수 있다.

결측치가 왜 발생했는지도 함께 확인해야 한다.

확인할 점

- 결측치 비율이 높은가?
- 특정 그룹에서만 결측이 많이 발생하는가?
- 결측 자체가 의미 있는 정보인가?
- 제거했을 때 데이터 손실이 큰가?
- 대체값이 데이터 분포를 왜곡하지 않는가?

---

6. 이상치 Outlier 처리

이상치는 일반적인 데이터 범위에서 크게 벗어난 값이다.

이상치는 모델 성능에 영향을 줄 수 있으며, 특히 평균이나 거리 기반 모델에 큰 영향을 줄 수 있다.

이상치 탐지 방법

방법| 설명
Boxplot| 사분위수 기준으로 이상치 확인
IQR| Q1, Q3 기준으로 이상치 범위 계산
Z-score| 평균과 표준편차 기준으로 이상치 확인
도메인 기준| 실제 업무 기준으로 비정상 값 판단

---

7. IQR 기준 이상치

IQR은 Interquartile Range의 약자로, 3사분위수와 1사분위수의 차이이다.

$$
IQR = Q3 - Q1
$$

일반적으로 다음 범위를 벗어나면 이상치 후보로 볼 수 있다.

$$
Lower Bound = Q1 - 1.5 \times IQR
$$

$$
Upper Bound = Q3 + 1.5 \times IQR
$$

이상치는 무조건 제거하기보다 실제 의미가 있는 값인지 확인해야 한다.

---

8. 이상치 처리 방법

이상치는 상황에 따라 다르게 처리한다.

방법| 설명
제거| 명백한 오류 데이터 삭제
대체| 상한값, 하한값 등으로 대체
변환| 로그 변환 등으로 영향 완화
유지| 실제 의미 있는 극단값이면 유지
별도 Feature 생성| 이상치 여부를 나타내는 변수 추가

예를 들어 구매 금액이 매우 큰 고객은 이상치처럼 보일 수 있지만, 실제로는 VIP 고객일 수 있다.

따라서 도메인 관점에서 판단해야 한다.

---

9. Encoding

Encoding은 범주형 변수를 모델이 학습할 수 있도록 숫자로 변환하는 과정이다.

머신러닝 모델은 대부분 숫자 데이터를 입력으로 사용하기 때문에 범주형 변수는 적절히 변환해야 한다.

대표적인 인코딩 방법은 다음과 같다.

- Label Encoding
- One-Hot Encoding
- Ordinal Encoding
- Target Encoding

---

10. Label Encoding

Label Encoding은 범주형 값에 숫자를 하나씩 부여하는 방법이다.

남성 → 0
여성 → 1

특징

- 간단하게 범주형 변수를 숫자로 바꿀 수 있다.
- 범주 개수가 많아도 컬럼 수가 늘어나지 않는다.
- 숫자 간 순서가 있다고 모델이 오해할 수 있다.

순서가 없는 범주형 변수에는 주의해서 사용해야 한다.

---

11. One-Hot Encoding

One-Hot Encoding은 각 범주를 새로운 컬럼으로 만들고, 해당 여부를 0 또는 1로 표시하는 방법이다.

색상| red| blue| green
red| 1| 0| 0
blue| 0| 1| 0
green| 0| 0| 1

특징

- 범주 간 순서 관계를 만들지 않는다.
- 선형 모델에서 자주 사용된다.
- 범주 개수가 많으면 컬럼 수가 크게 늘어날 수 있다.

---

12. Ordinal Encoding

Ordinal Encoding은 순서가 있는 범주형 변수에 숫자를 부여하는 방법이다.

예를 들어 만족도처럼 순서가 있는 변수에 사용할 수 있다.

낮음 → 1
보통 → 2
높음 → 3

특징

- 범주 간 순서가 있을 때 적합하다.
- 순서가 없는 변수에 사용하면 잘못된 관계를 만들 수 있다.

---

13. Target Encoding

Target Encoding은 범주형 변수의 각 범주를 Target의 평균값 등으로 변환하는 방법이다.

예를 들어 지역별 평균 구매 금액을 사용해 지역 변수를 숫자로 바꿀 수 있다.

특징

- 범주 수가 많은 변수에 사용할 수 있다.
- Target 정보를 활용하므로 성능 향상에 도움이 될 수 있다.
- Data Leakage와 과대적합에 주의해야 한다.
- Cross Validation과 함께 적용하는 것이 좋다.

---

14. Feature Scaling

Feature Scaling은 변수들의 값 범위를 비슷하게 맞추는 과정이다.

Feature의 스케일이 다르면 일부 모델에서 특정 변수가 과도하게 큰 영향을 줄 수 있다.

특히 거리 기반 모델이나 경사하강법 기반 모델에서는 스케일링이 중요하다.

---

15. Standardization 표준화

Standardization은 평균을 0, 표준편차를 1로 변환하는 방법이다.

$$
z = \frac{x - \mu}{\sigma}
$$

- $x$: 원래 값
- $\mu$: 평균
- $\sigma$: 표준편차

특징

- 평균 0, 표준편차 1로 변환한다.
- 정규분포에 가까운 데이터에서 자주 사용한다.
- Logistic Regression, SVM, PCA 등에 자주 사용된다.

---

16. Normalization 정규화

Normalization은 값을 특정 범위로 변환하는 방법이다.

대표적으로 Min-Max Scaling은 값을 0과 1 사이로 변환한다.

$$
x' = \frac{x - x_{min}}{x_{max} - x_{min}}
$$

특징

- 값의 범위를 0과 1 사이로 맞춘다.
- 거리 기반 모델에서 사용할 수 있다.
- 이상치에 민감할 수 있다.

---

17. Scaling이 중요한 모델

스케일링은 모든 모델에 항상 필요한 것은 아니다.

모델| Scaling 필요성
Linear Regression| 필요한 경우 많음
Logistic Regression| 필요
KNN| 매우 중요
K-Means| 매우 중요
SVM| 매우 중요
PCA| 매우 중요
Decision Tree| 상대적으로 덜 중요
Random Forest| 상대적으로 덜 중요
Gradient Boosting Tree| 상대적으로 덜 중요

거리 기반 모델과 선형 모델에서는 스케일링이 특히 중요하다.

---

18. 파생 변수 생성

파생 변수 생성은 기존 변수를 조합하거나 변환하여 새로운 Feature를 만드는 과정이다.

도메인 지식을 활용하면 모델이 더 쉽게 학습할 수 있는 유용한 변수를 만들 수 있다.

예시

기존 변수| 파생 변수
생년월일| 나이
주문일자| 주문 월, 주문 요일
매출, 고객 수| 고객당 매출
총 구매 금액, 구매 횟수| 평균 구매 금액
첫 구매일, 최근 구매일| 고객 활동 기간

---

19. 날짜 Feature Engineering

날짜 데이터는 그대로 사용하기보다 여러 의미 있는 변수로 분해할 수 있다.

예시

- 연도
- 월
- 일
- 요일
- 주말 여부
- 공휴일 여부
- 분기
- 계절
- 특정 이벤트 전후 여부
- 기준일로부터 경과 일수

날짜 변수는 시계열 패턴이나 계절성을 반영하는 데 유용하다.

---

20. 로그 변환 Log Transformation

로그 변환은 값의 분포가 한쪽으로 치우쳐 있을 때 사용할 수 있는 변환이다.

예를 들어 매출, 소득, 구매 금액처럼 큰 값이 일부 존재하는 변수에 사용할 수 있다.

$$
x' = \log(x + 1)
$$

"+1"을 하는 이유는 값이 0일 때 로그 계산이 불가능하기 때문이다.

효과

- 큰 값의 영향을 줄일 수 있다.
- 오른쪽으로 치우친 분포를 완화할 수 있다.
- 이상치의 영향을 줄일 수 있다.

---

21. Binning 구간화

Binning은 연속형 변수를 구간으로 나누어 범주형 변수처럼 사용하는 방법이다.

예를 들어 나이를 연령대로 나눌 수 있다.

0 ~ 19세 → 10대 이하
20 ~ 29세 → 20대
30 ~ 39세 → 30대

특징

- 비선형 관계를 단순하게 표현할 수 있다.
- 해석이 쉬워질 수 있다.
- 너무 많은 구간을 만들면 과대적합이 발생할 수 있다.
- 구간 기준은 도메인 지식이나 데이터 분포를 참고해야 한다.

---

22. Interaction Feature

Interaction Feature는 두 개 이상의 Feature를 조합하여 만든 변수이다.

단일 변수만으로는 드러나지 않는 관계를 표현할 수 있다.

예시

변수 조합| 의미
가격 / 면적| 단위 면적당 가격
총 구매 금액 / 구매 횟수| 평균 구매 금액
이용 횟수 × 이용 기간| 활동성 지표
광고 클릭 수 / 노출 수| 클릭률 CTR

Interaction Feature는 모델이 변수 간 상호작용을 더 쉽게 학습하도록 도와준다.

---

23. Feature Selection

Feature Selection은 여러 Feature 중 모델에 유용한 Feature만 선택하는 과정이다.

불필요하거나 중복된 Feature를 제거하면 모델이 더 단순해지고, 과대적합을 줄일 수 있다.

목적

- 모델 성능 개선
- 과대적합 감소
- 학습 속도 향상
- 해석력 향상
- 노이즈 제거

---

24. Feature Selection 방법

방법| 설명
Filter Method| 통계적 기준으로 변수 선택
Wrapper Method| 모델 성능을 기준으로 변수 조합 선택
Embedded Method| 모델 학습 과정에서 변수 중요도 반영

예시

- 상관관계 확인
- 카이제곱 검정
- SelectKBest
- RFE
- Lasso
- Tree 기반 Feature Importance

---

25. Feature Importance

Feature Importance는 모델이 각 Feature를 얼마나 중요하게 사용했는지를 나타낸다.

Tree 기반 모델에서는 Feature Importance를 비교적 쉽게 확인할 수 있다.

주의할 점

- Feature Importance는 모델 기준의 중요도이다.
- 중요도가 높다고 해서 인과관계를 의미하지는 않는다.
- 상관관계가 높은 Feature가 여러 개 있으면 중요도가 나뉠 수 있다.
- 해석이 필요한 경우 SHAP 같은 방법을 함께 사용할 수 있다.

---

26. Data Leakage 주의

Feature Engineering에서 가장 주의해야 할 문제 중 하나는 Data Leakage이다.

Data Leakage는 모델이 실제 예측 시점에는 알 수 없는 정보를 학습 과정에서 사용하게 되는 문제이다.

예시

- Target 이후에 발생한 정보를 Feature로 사용
- Test Data를 기준으로 Scaling 수행
- 전체 데이터 평균으로 결측치를 대체
- Target과 직접 연결된 변수를 Feature로 사용
- 미래 정보를 사용해 과거를 예측

Data Leakage가 발생하면 모델 성능이 실제보다 좋게 보일 수 있다.

---

27. Train 기준 전처리

전처리와 Feature Engineering은 반드시 Train Data를 기준으로 수행해야 한다.

예를 들어 Scaling을 할 때는 Train Data의 평균과 표준편차를 구하고, 그 기준을 Validation/Test Data에 적용해야 한다.

Train Data로 기준 학습
→ Train Data 변환
→ 같은 기준으로 Validation/Test Data 변환

Validation/Test Data의 정보를 전처리 기준을 만드는 데 사용하면 Data Leakage가 발생할 수 있다.

---

28. Feature Engineering 사용 시 주의할 점

- 문제 목적에 맞는 Feature를 만들어야 한다.
- Target Leakage가 발생하지 않도록 주의해야 한다.
- Train/Test Split 이후 전처리 기준을 학습해야 한다.
- 너무 많은 파생 변수는 과대적합을 유발할 수 있다.
- 도메인 지식과 데이터 탐색을 함께 활용해야 한다.
- Feature Engineering 전후의 모델 성능을 비교해야 한다.
- 해석 가능성이 중요한 문제에서는 단순한 Feature가 더 좋을 수 있다.

---

29. 정리

- Feature Engineering은 모델이 잘 학습할 수 있도록 Feature를 만들고 변환하는 과정이다.
- 결측치 처리는 제거, 평균 대체, 중앙값 대체, 최빈값 대체 등을 사용할 수 있다.
- 이상치는 오류인지 의미 있는 극단값인지 확인해야 한다.
- Encoding은 범주형 변수를 숫자로 바꾸는 과정이다.
- One-Hot Encoding은 순서 없는 범주형 변수에 자주 사용된다.
- Ordinal Encoding은 순서가 있는 범주형 변수에 적합하다.
- Scaling은 변수의 값 범위를 조정하는 과정이다.
- KNN, K-Means, SVM, PCA 등은 Scaling이 중요하다.
- 파생 변수는 기존 변수를 조합하거나 변환하여 만든다.
- 날짜 변수는 연도, 월, 요일, 주말 여부 등으로 분해할 수 있다.
- 로그 변환은 치우친 분포와 큰 값의 영향을 완화할 수 있다.
- Feature Selection은 중요한 Feature만 선택하는 과정이다.
- Feature Engineering 과정에서는 Data Leakage를 반드시 주의해야 한다.
